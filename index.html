01 / THE IDEA

What problem does it solve?

K-Nearest Neighbors is a supervised method that predicts a new observation by finding the K training examples closest to it. For classification, neighbours vote on the class; for regression, their target values are averaged. KNN is intuitive because a prediction is grounded in nearby examples rather than a fitted global equation.

A new data point may not have a known label, but similar labelled examples can provide evidence. KNN formalises “similar” through a distance measure. The method is only as useful as its feature representation, scaling, distance metric, and chosen neighbourhood size.

Euclidean distance: d(x,z) = √Σⱼ(xⱼ − zⱼ)²

02 / METHOD

How it works, step by step

  1. 01
    Choose relevant features and a target label.
  2. 02
    Split training and test observations before model selection.
  3. 03
    Scale numeric features so large-range variables do not dominate distance.
  4. 04
    Calculate distances from a new row to training rows and select the K nearest.
  5. 05
    Use majority vote or a distance-weighted vote; evaluate on held-out observations.

03 / VOCABULARY

Concepts worth knowing

K

Number of neighbours consulted. Very small K can be noisy; very large K can blur local patterns.

Distance metric

Euclidean distance is common for scaled numeric features; Manhattan or other metrics may suit other data.

Majority vote

The most frequent class among the selected neighbours becomes the prediction.

Distance weighting

Closer neighbours can receive more influence than farther ones.

Curse of dimensionality

In many high-dimensional spaces, distances become less discriminating and neighbourhoods become less useful.

Lazy learning

KNN stores training examples and delays most computation until prediction time.

04 / IN PRACTICE

A realistic use case

A botanical classifier can compare a new flower’s measured features with previously labelled flowers. If most nearby examples belong to one species, that species is predicted. In practice, feature scales and the choice of K can change the neighbourhood substantially.

Questions to ask before trusting the result

  • Does the data represent the population or workflow where the model will be used?
  • Are important features missing, noisy, or measured after the outcome?
  • Would a wrong prediction have unequal costs for different groups?
  • Can the result be checked on data not used to build or tune the method?

07 / INTERPRETATION

How to interpret the output

Class-distribution charts reveal imbalance. A feature scatter plot shows whether classes occupy distinct regions. Validation performance across K helps balance noise and oversmoothing. A confusion matrix shows which classes are commonly confused; use per-class recall when mistakes are not equally costly.

Do not confuse a pattern with proof

A plot is evidence about the rows and variables it displays. It does not by itself establish causation, guarantee performance on future data, or show that a model will remain reliable after the data distribution changes. Document assumptions and evaluate the method in the context where it will be used.

08 / TRADE-OFFS

Strengths and limitations

Where it helps

  • Easy to explain and implement
  • Can model nonlinear class boundaries
  • No explicit training optimisation is required
  • Supports classification and regression

Where to be careful

  • Prediction can be slow for large training sets
  • Sensitive to feature scaling and irrelevant features
  • Memory-intensive because examples are retained
  • High-dimensional data can weaken distance meaning

When should you use it?

Use KNN for small-to-medium datasets with meaningful distances and a clear feature representation. Compare several K values and metrics, and consider tree-based or approximate-neighbour methods for larger datasets.

10 / TAKEAWAY

What to remember

Use KNN for small-to-medium datasets with meaningful distances and a clear feature representation. Compare several K values and metrics, and consider tree-based or approximate-neighbour methods for larger datasets.

The best workflow is not simply to run an algorithm and show a graph. It is to define the question, prepare the data, explain the method, examine evidence, test limitations, and communicate what can reasonably be concluded.

11 / WORKED EXAMPLE

Worked example: why scaling matters

Imagine one feature ranges from 0 to 10 while another ranges from 0 to 10,000. Without scaling, the larger-range feature can dominate Euclidean distance even if it is not more informative. A pipeline scales using training data and then applies the same transformation to new examples, preventing information from the test set from leaking into preprocessing.

  • Fit the scaler only on training data.
  • Choose K with cross-validation rather than guessing from one split.
  • Compare per-class recall when class errors have different consequences.

12 / REPRODUCIBLE WORKFLOW

Implementation blueprint

This optional Python example shows the usual workflow for the included CSV. It is source code for running locally, not code that runs inside this static article. Install the listed libraries first, keep the dataset file beside the script, and use the printed output as a starting point for interpretation—not as a substitute for checking assumptions.

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier
from sklearn.metrics import classification_report

df = pd.read_csv("flower_measurements_teaching_data.csv")
X = df[["petal_length", "petal_width"]]
y = df["species"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=7, stratify=y
)
model = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5))
model.fit(X_train, y_train)
print(classification_report(y_test, model.predict(X_test)))

How to read it: the code selects the relevant columns, applies the algorithm, and prints a summary or evaluation. Results can vary with random sampling and package versions. For a real project, document the split, parameters, metrics, and any preprocessing choices.

13 / QUALITY CHECK

Common mistakes to avoid

  • Using unscaled features with very different units.
  • Choosing K using the test set repeatedly.
  • Assuming distance remains meaningful in very high dimensions.

Before publishing a conclusion, ask whether the data supports the statement, whether the chart matches the stated method, and whether a reader could reproduce the workflow from the included files.
